# 🚀 LogicLens — System Reference & Handover Manual

This developer reference was compiled to serve as a complete project handover sheet. If you are starting a new chat or taking over development, this document contains all the information you need to understand, run, compile, and extend the **LogicLens** workspace.

---

## 📂 1. Technical Architecture & Directory Map

LogicLens is structured as a type-safe **TypeScript pnpm monorepo** consisting of isolated, reusable packages and standalone application servers:

*   **`frontend/`**: Single Page Application built with **React** (v19) and **Vite**. Contains the main workspace interface, Monaco Editor sync, Zustand store, and the custom simulation engine.
*   **`backend/`**: Express.js REST API server. Handles routing for authentications, traces, admin panels, and payment integrations.
*   **`database/`**: Mapped schema definitions using **Drizzle ORM** (PostgreSQL/SQLite) and config files.
*   **`packages/api-spec/`**: Contains `openapi.yaml` describing REST contracts, and `orval.config.ts` for automatic code generation.
*   **`packages/api-zod/`**: Autogenerated Zod validation schemas for request bodies.
*   **`packages/api-client-react/`**: Autogenerated TanStack Query React hooks for frontend REST requests.

---

### Frontend Client

## 🧠 3. TraceWise AI Simulation & Control Flow Engines

The core logic simulator is entirely browser-based, avoiding server compilation risks.

### 1. Tokenizer & Statement Parser
Located in `frontend/src/engines/simulate/simulationEngine.ts`, this engine:
*   Extracts the code inside `public static void main(String[] args)` blocks.
*   Splits lines into Statement tokens: declarations, assignments, print/output, conditionals (if-else chains), loops (for, while), and early loop terminations (break).

### 2. Symbolic Execution Engine
*   Executes statements step-by-step using a virtual `VariableState` memory grid.
*   Unrolls loop blocks into discrete, labeled loop iterations (e.g., Iteration 1, Iteration 2) instead of jumping on headers, allowing scrubber timeline scrollbacks.
*   Emulates accurate Java Integer Division by auto-truncating division operations between integer variables.

### 3. Graph Construction & Flowchart Layout
*   `buildFlowNodes.ts` & `buildFlowEdges.ts` parse syntax nodes and draw React Flow components.
*   Loops generate explicit loop-back edges, and conditionals draw `true`/`false` paths.
*   Nodes glow dynamically with neon borders depending on whether their state is `completed`, `current`, or `pending`.

### 4. Code Highlight Syncer
*   A Zustand store maps the active `ExecutionStep.lineNumber` directly to Monaco Editor line decorators, auto-scrolling to keep loops and branches centered.

## 🗄️ 4. Relational Database Schema Mapping

LogicLens uses PostgreSQL tables managed by Drizzle. The schemas are configured in `database/src/schema/`:

### 1. Users (`users` table)
Tracks profiles, access rights, and billing states:
*   `id`: Serial (Primary Key)
*   `name` / `email` / `passwordHash`: Credentials and profiles
*   `role`: User status (`student` | `admin`)
*   `stripeCustomerId` / `subscriptionStatus`: Stripe subscription data
*   `planType`: Tier limit constraints (`free` | `pro` | `enterprise`)

### 2. Saved Traces (`saved_traces` table)
Stores past execution runs:
*   `id`: Serial (Primary Key)
*   `userId`: Owner foreign-key relationship
*   `title` / `category` / `subtype`: Trace metadata
*   `code`: Raw Java source input
*   `customInputs`: JSONB map of variable overrides (e.g., `{"n": 123}`)
*   `traceSummary`: Calculated post-run summary text
*   `finalOutput`: Captured terminal standard outputs
*   `shareSlug`: Slug for public read access
*   `isPublic`: Boolean status flag

### 3. Favorite Programs (`favorite_programs` table)
Connects users to pre-written algorithms:
*   `id`: Serial
*   `userId` / `programId` / `programName` / `programCategory`

### 4. UPI Payments (`upi_payments` table)
Tracks local payment transactions:
*   `id`: Serial (Primary Key)
*   `userId`: Buyer foreign-key
*   `planType`: Subscription tier (`pro` | `institutional`)
*   `amount`: Pricing in INR
*   `paymentMethod`: Payment channel (`upi_gpay` | `upi_phonepe` | `card`)
*   `paymentRequestId`: Real Instamojo transaction ID or mockup UUID
*   `status`: Current state (`pending` | `completed` | `failed`)

## 🚀 7. Developer Playbook (How to Run & Dev)

Ensure you follow these commands when building or launching the project:

### 1. Installation
Install all dependencies in the monorepo root:
```bash
pnpm install
```

### 2. Run Development Server
Launches the frontend Vite app and Express API concurrently:
```bash
pnpm dev
```
*Frontend opens at `http://localhost:5173`, and Backend opens at `http://localhost:3000` (or `5000`).*

### 3. Generate Schema & Database Migrations
Push local schemas to PostgreSQL:
```bash
pnpm db:push
```

### 4. Build Code Client Hooks
Generates React Query hooks and Zod parameters from the OpenAPI specification:
```bash
pnpm --filter "@workspace/api-spec" run generate
```

### 5. Compile Project Assets
Builds all local package folders, backend server bundles, and frontend assets for production:
```bash
pnpm build
```

### 6. Regenerate PDF Handover Manual
Compiles the latest manual to `LogicLens_Complete_Handover_Manual.pdf`:
```bash
node generate_handover_manual.js
```
